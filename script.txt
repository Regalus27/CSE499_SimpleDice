Simple Dice Final Presentation Script
CSE 499 - Final Presentation.

Introduction
Hello everyone. This week our group is giving a presentation of our CSE 499 project Simple Dice.
Simple Dice - is a web application that aims to make rolling dice simple, but with features such as accounts, roll storage, activities, stats plus light and dark themes.
During this project we not only wanted to build this great dice roller, we also wanted to create our own web-application and allow for users to interact with their own data.

Project Purpose
Goal of Simple Dice A simple and fast way of using a digital die.
The user can decide what style of dice they want and how many they want to be rolled. Our app receives the outcome and stores the outcome in the database.
Our app included another thing that was outside a dice roller - user accounts, authentication, activities, statistics, themes etc.

Main Features
Our application features many exciting features.
Number one, the dice roller. Our users will be able to choose which type of die they want to roll. We have a D4, D6, D8, D10, D12, D20, and D100.
Then the user can decide how many of that die he wants to use. And our app will add up and display.
In addition, we have an API route that persists the dice-roll to our database.

Registration
Another feature I worked on was registering the user.
This is where a new user will register for an account to log on our application with their user name and password.
For a pristine, clean registration, we maintained the structure of our database, so that it contains only the username and the information of the password that we need to have.
We check the data entered by them before any insertion into our database.
For instance, we verify that the username matches the regex we need to match and that the password is of minimum length.

Password Security
We also implemented additional security measures to keep the user's passwords safe.
The user's password that we stored into our database We salted and hashed the input password from the user with the bcrypt.
This prevents the app from ever knowing the real password.
Instead, bcrypt converts the password of a user to another inaccessible form.
Some data is even better than text and that's crucial for our login and security features.

Login and Authentication
The application authenticates the Login credentials to determine whether the user actually is a user of our application.
Logged-in users can enter their login details on this page to inform our authentication system of their identity.
Authentication route in Sprint 3. During sprint 3, the login page, all the API routes related to login, and the session authenticating itself were created.

Dark and Light Mode
I also worked on the Dark and Light Mode feature.
We developed two separate color palettes for our application.
The light mode is the one that uses light background colors and dark text. The dark mode is the opposite, and uses dark background colors and light text.
Instead of using multiple pages and/or components for each theme, we can use CSS variables to set the background, text, border, card, and input color.
If the user changes the theme, the change to the CSS variables will reflect the new theme.

Saving the Theme Preference
And, we also wanted our application to store which theme you like for when you returned to the application again later.
We do this with a cookie in your browser called simpledice-theme.
When a user switches to dark mode we assign dark value to the cookie.
And likewise with the light mode, where light is the value of that very same cookie.
So we save the value of the cookie, and when the user visits us again we reset the simpledice-theme to whatever the user had set it.
This saves them from selecting the background theme again each time they visited our app, which would be pretty annoying.

Shared Code Organization
In development we have improved the organization of the code so that everything is more manageable.
In the past we used a large number of lib directories and some duplicated code such as database calls.
We've focused on keeping the code organized so that any duplicate or common code resides in a single spot.
All of our connections to our database, MongoDB, are simply reused from getDatabase() for each of our APIs like registration and dice-roll.
This helps to reduce code duplication, making our code easier to manage.
